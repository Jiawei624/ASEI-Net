# ASEI-Net：运行结果、评价协议与模型细节分析

日期：2026-11-06。实验依据为 `result/001/*.json` 与 `result/001/log/`，四个数据集均只有 seed 42 的一次结果。文献依据为已核验的一手会议页面、作者公开稿及下文列出的官方代码。调参值和模型改进属于待验证候选，不代表已获得性能提升。

## 1. 评价协议与结果文件

固定计算 `metrics.txt` 的 16 个标签指标和 6 个分数指标。回归误差、额外阈值运行点、独立事件诊断和单点延迟基准不进入常规实验。比例和面积保持 0–1，ADD 的单位为采样点。

| 组别 | 指标 | 输入及解释 |
|---|---|---|
| 原始点级 | accuracy、precision、recall、f_score | 正常验证段确定的固定阈值产生原始报警 |
| 点调整 | adjust_accuracy、adjust_precision、adjust_recall、adjust_f_score | 命中真实异常区间任意一点后补全该区间，仅用于这四项评价 |
| 区间与关联 | rprecision、rrecall、rf、affiliation_precision、affiliation_recall、affiliation_f | 原始报警；定义不同于点级 precision/recall，数值不能直接互相替代 |
| 排名与延迟 | precision_at_k、add | P@K 使用连续分数，K 为真实异常点数；ADD 使用点调整前首次报警，漏检计事件长度 |
| 连续分数 | auc_roc、auc_pr、R_AUC_ROC、R_AUC_PR、VUS_ROC、VUS_PR | 原始连续分数；auc_pr 是 Average Precision，Range/VUS 保留现有窗口定义 |

部署阈值只由正常验证分数的上分位确定，使用严格大于；测试标签不参与训练、模型选择和阈值确定。P@K 中由标签确定 K 属于评价定义，与选择部署阈值不同。完整时间轴保留预热及缺测位置：这些位置不报警，分数排列在所有有效分数之后。

P@K 的边界同分采用确定性的比例分摊。设第 K 大分数为 b，严格大于 b 的点集合为 A，同分集合为 E，则

`P@K = [sum(y[A]) + (K-|A|) * mean(y[E])] / K`。

这避免了将二值报警传给严格分位比较时，结果退化为 0 或 recall 的问题。当前协议标识为 `detection22_score_topk_v2`。其余 21 个指标保留已有数值定义；不可直接混用旧二值 P@K 与当前 P@K。

`result/001/metrics_22.csv` 仅转录所提供文件中可验证的值。SWAT 的四个 `adjust_*` 和 P@K 未在其 JSON 中提供，保留空白；其他三个数据集的旧 P@K 也留空并标记 `legacy_binary_input`。仅凭四个 JSON 无法恢复原始逐点分数和报警，不能补造这些值。

成功完成的常规实验保留：

```text
outputs/runs/<Run ID>/
  run.json
  metrics.csv
  <dataset>/<entity>/seed_<seed>/detectors/<variant>/bundle.pt
```

同次命令的所有实体和种子进入同一个 `metrics.csv`，每行由 dataset/entity/seed/variant 标识。模型文件包含两个阶段的最优权重、原型、标准化统计、阈值、配置、来源信息、训练历史和最终指标。训练中断时保留工作文件；最终模型及 CSV 成功写入后才清理缓存、重复权重、预测数组和中间 JSON。`--keep-intermediates` 或 `--diagnostics` 保留检查材料。

`aggregate` 按数据集和 seed 输出一个 `dataset_metrics.csv`，实体等权，评价协议分组；同 seed 的重复训练不算额外种子。`export` 用于统一导出现有结果，支持从旧预测数组快速补算标签指标。

## 2. 本次结果反映的问题

以下原始 F1、AP、ROC-AUC 和 ADD 来自所提供的 JSON；正常误报率来自其中的 `metrics.event.normal_false_positive_rate`。该诊断用于分析已有结果，不额外写入常规 22 指标 CSV。

| 数据集 | 原始 F1 | 点调整 F1 | AP | ROC-AUC | 测试正常点误报率 | ADD |
|---|---:|---:|---:|---:|---:|---:|
| PSM | 0.0323 | 0.9264 | 0.4371 | 0.6499 | 0.22% | 118.06 |
| SMD | 0.1639 | 0.6009 | 0.1452 | 0.6655 | 4.35% | 33.23 |
| SWAT | 0.3727 | 缺失 | 0.2241 | 0.7632 | 38.27% | 58.54 |
| PUMP | 0.3086 | 0.3200 | 0.1391 | 0.6912 | 47.46% | 3.67 |

**PSM 存在严重漏检。** 原始 recall 仅 1.65%，却因命中部分长异常区间而得到 0.9264 的点调整 F1。这两项没有计算冲突，但点调整值不能证明持续异常覆盖能力。其可评分异常点比例为 99.9877%，预热丢失不足以解释如此低的召回。

**SWAT、PUMP 存在严重正常误报。** 两者正常验证超阈比例均约 1%，测试正常误报却达到 38.27% 和 47.46%。这与正常模式覆盖不足、训练/测试分布差异或特征对合法变化过敏相容，尚不能从汇总文件确定唯一原因。PUMP 的高 recall 和短 ADD 同时伴随大量误报，不能单独视为检测效果好。

**仅降低 alpha 不足以解决问题。** 已有敏感性结果中，即使 alpha=0.001，SWAT、PUMP 的测试正常误报仍分别为 26.06%、32.83%，同时 ADD 增大。不能根据这些测试结果挑选最佳 alpha；应预先固定正常运行预算，再改进正常表征和泛化。

**训练过程也存在不同模式。**

| 数据集 | 阶段一最佳/实际轮数 | 阶段一最佳验证损失 | 阶段一平均秒/轮 | 阶段二最佳/实际轮数 | 阶段二最佳验证损失 | 阶段二平均秒/轮 |
|---|---:|---:|---:|---:|---:|---:|
| PSM | 14 / 24 | 5.411337 | 93.5 | 1 / 9 | 0.666264 | 81.3 |
| SMD | 7 / 17 | 1.656994 | 702.5 | 2 / 10 | 0.580840 | 83.2 |
| SWAT | 7 / 17 | 0.526952 | 722.1 | 30 / 38 | 0.341825 | 154.0 |
| PUMP | 8 / 18 | 2.971557 | 98.8 | 5 / 13 | 0.555093 | 77.2 |

PSM 阶段二验证损失从第 1 轮的 0.6663 上升至第 9 轮的 0.9858，而训练损失持续下降；SMD 也在第 2 轮后持续波动、恶化。这支持优先检查过拟合和合成训练/验证域差异，不能简单认为训练轮数不够。SWAT 直到第 30 轮仍有显著改善，不宜四个数据集统一大幅缩短阶段二。

PUMP 阶段一训练损失从 3.76 增至约 31.40 后回落，说明训练早期存在明显不稳定。阶段一当前日志只给总损失，无法判断预测、边际 VQ、联合 VQ 各自的贡献，也不能据此断言原型坍塌。

SMD 阶段一约占已记录三阶段训练时间的 89%，SWAT 约占 64%，效率优化应优先考虑阶段一。该时间统计不含完整的数据读取、校准、测试和指标计算耗时。

## 3. 保持模型结构不变的调参候选

下表的已运行配置来自 `result/001`，候选值尚未验证为最优。当前首先在 PSM/PUMP 上执行稳定性调参，运行配置如下；模型结构、batch、任务预算和 alpha 保持既有设置。

| 当前配置文件 | 阶段一 lr | 阶段一 patience | 阶段二 lr | 阶段二 patience | 阶段一 batch / 阶段二 batch_pairs |
|---|---:|---:|---:|---:|---:|
| `configs/psm.yaml` | 0.0003 | 6 | 0.0003 | 8 | 128 / 32 |
| `configs/pump.yaml` | 0.0001 | 6 | 0.0003 | 8 | 64 / 16 |

这组配置用于观察整体稳定性，不将结果变化归因于某个单独参数。PSM 使用 GPU0、PUMP 使用 GPU1 时可并行运行；改变训练参数后新建实验，不续用原参数的检查点。SMD/SWAT 暂沿用现有配置。

| 对象 | 已运行配置 | 优先候选 | 依据与判断条件 |
|---|---|---|---|
| 四个数据集的阶段一早停 | patience=10 | 6 | 按本次已观察轨迹回放，均仍选择相同最佳轮次；SMD/SWAT 分别可少跑约 47/48 分钟。新实验仍需确认没有更晚改善 |
| PSM 阶段二 | lr=1e-3，patience=8 | 先只试 lr=3e-4；随后比较 1e-4 | 最佳点在首轮，继续训练验证明显恶化。先观察合成验证损失及正常验证分数分布，不以测试 F1 选学习率 |
| SMD 阶段二 | lr=1e-3，patience=8 | 先试 lr=3e-4 | 最佳点在第 2 轮；保留任务数量和批量，隔离学习率影响 |
| PUMP 阶段一 | lr=3e-4，warmup=5 | 单独试 lr=1e-4 | 早期总损失显著抬升；需核对是否只是收敛变慢，后续再考虑分支权重 |
| PUMP 阶段二 | lr=1e-3 | 单独试 3e-4 | 验证早于训练收敛；高误报的根因仍可能在正常覆盖，学习率没有解决保证 |
| SMD 阶段一效率 | stride=1，batch=192 | stride=4，保留 batch=192 | 正常滑动窗口高度重叠；验证仍逐点，原型最终统计仍使用全部拟合点 |
| SWAT 效率 | 本次实际 batch=64，batch_pairs=16，feature_batch=128 | 先验证当前 YAML 的 128 / 24 / 256；另开实验再试 stride=4 | 本次 SWAT 使用保存的旧配置，日志不能证明当前较大批量的速度和效果 |
| SMD/SWAT 模型容量 | d=96，layers=2，W=256 | 若仍过慢，分别比较 d=64 或 layers=1 | 会改变模型容量，需单独对照；先保留 W，避免把历史预算和容量同时改变 |

stride=4 不意味着整轮时间严格降至四分之一。SMD 的训练目标约减少至四分之一，但验证仍有约 14 万个逐点目标；按目标数量粗算，训练加验证的工作量约为原来的 40%，尚未计入其他开销。学习率、原型复活按 epoch 的节奏、每轮优化步数也会变化，需重新训练。

SMD 的已记录本次调用峰值约为 11.87 GiB，不建议先继续盲目放大 batch。PSM JSON 中只有约 33 MiB 的峰值且测试特征耗时为 0，明显属于补算调用的统计，不能用来推断阶段一训练显存余量。峰值必须结合产生该 JSON 的实际阶段解释。

`block_length` 当前为 256。增至 512 会改变截断反向传播范围和显存需求；增大 `batch_pairs` 则可能增加填充到最长任务的浪费。两者应分开测试。`fixed_retention` 对默认 full 变体不生效，调它不会改变当前学习式门控。仅修改 `feature_batch_size` 影响冻结特征提取，不直接减少两阶段训练的更新步数。

建议先保留 alpha=0.01、W=256 和任务族，依次比较早停、阶段二学习率和大数据集 stride。更改训练 batch、stride、学习率或容量后新建时间戳实验；显式续跑用于完成原参数实验。

## 4. 方案与代码的一致性

已核对 `asei/model.py`、`training.py`、`tasks.py`、`features.py`、`data.py` 和阶段调度，确认以下具体路径：

- 一步预测读取 `[t-W,t)`；当前观测仅进入异常检测描述和原型查询。
- 自身历史编码按通道独立；外部历史聚合使用零对角关系矩阵。
- 原型解码从已学习码字生成，不把当前查询直接拼入解码器。
- 阶段二冻结正常表征，干净/扰动轨迹分别重新计算特征；标签只进入损失。
- 门控对齐到上一时刻正常状态，共享 GRU 的两轨迹接口与方案一致；缺测时按来源可用性处理。
- 阈值由正常验证分数确定，测试标签仅供评价。

小规模 CPU 检查中，逐点与块执行、离线与流式的最大分数差均约为 `2.98e-8`；修改未来样本不改变过去分数。改变目标通道自身历史不会改变其关系分支预测，也不会改变其他通道的自身分支预测。该结果验证这些具体路径，没有替代完整数据集 GPU 实验。

未发现能够直接解释全部差性能的目标泄漏或轨迹时序索引错误。以下问题属于可从结构推导的局限与待验证优化：

1. `score=max(channel_logits)` 使单个时刻的分类梯度主要流向获胜通道。合成扰动虽然知道受影响通道，当前训练仅使用全局时间标签，未利用这部分定位信息。
2. 所有通道统一执行连续幅值、方差、形态描述及扰动。对 SWAT 的离散状态变量，连续噪声或均值/方差匹配供体可能产生不合法状态值，形成过于容易的合成任务。PUMP 是否存在同类离散变量问题需先核对变量类型，不能直接类推。
3. 正常轨迹的适配器仍接收由观测历史产生的预测值；原型编号也由当前观测查询。冻结参数不等于正常状态输入完全隔离异常，持续异常下两轨迹仍可能共同漂移。
4. `normal_loss` 将预测和两个原型分支相加，VQ 内部权重固定。总损失改善不必然等于对检测有用的正常模式覆盖改善；现有结果缺少分支损失及原型使用率证据。
5. 关系矩阵是静态非负受限聚合，不应被解释为已识别的物理因果图。非负权重本身不证明模型无法表达负相关，因为通道编码和读出仍是可学习的。

已有工作覆盖了“原型＋多来源证据＋两阶段学习”这一组合，单靠这些模块难以支撑方法区别。更具体、可检验的贡献是：正常原型如何驱动共享状态空间中的参照轨迹，以及对齐机制是否改善长异常和恢复。应以同冻结表征的 MLP、普通 GRU、无对齐双轨迹等对照验证，而不是依赖点调整 F1。

## 6. 保留总体流程的备选细节改进

以下均为本项目的设计候选，尚未实现。它们保留正常数据拟合、冻结正常参照、合成任务训练共享双轨迹、正常验证单阈值的流程。文献提供机制启发，实际收益和根因归属必须用项目实验确认。

### A. 增加受扰通道辅助监督，保留全局检测头

**优先级：高；改动量：小到中。** 在任务 recipe 已有的事件区间和通道集合上构造通道标签，为受扰通道和未受扰通道增加小权重 BCE。先保留现有 max 读出，辅助项权重可比较 0.1、0.3。全局时间标签的监督保持原有阶段均衡。

这直接针对 max 梯度仅流向获胜通道的问题，减少由未受扰通道承担正例分类的捷径。若进一步比较平滑读出，可单独使用 `tau * log(mean(exp(logit/tau)))`，训练和推断必须一致。它可能稀释单通道弱异常，不能默认优于 max。通道角色建模的动机与 TeamWork 一致，但辅助标签方案是针对现有任务结构的推断。

**验证：** 相同冻结表征、相同任务，比较原始 F1、AP、Range F1、ADD；用调试模式核对获胜通道是否落在实际受扰集合。

### B. 补充合法正常变化，避免把“变化”本身学成异常

**优先级：高；改动量：中。** 保留四类异常任务，另加入经过正常规则筛选的正常增强：同步的相位/幅值变化、正常工况内的片段变换、关系保持的小变化。可先将部分负例预算分配给该组，不直接增加总训练预算。

CAROTS 的正常保持与异常破坏双向增强提供了直接启发。不能把任意扰动都标为正常，也不能把本项目的关系矩阵当作真实因果图。应以正常数据中的联动关系和已知状态支持约束增强，并避免与异常任务定义重叠。

**验证：** 先看未参与训练的正常验证块上是否减少误报，并保留原四族的识别能力；然后进行一次锁定配置的最终测试。SWAT/PUMP 的测试高误报支持优先做此项，但不证明此项能够覆盖其全部分布差异。

### C. 对离散状态变量采用类型相容的描述与扰动

**优先级：高，优先 SWAT；改动量：中。** 从正常拟合段及变量语义确定类型。连续传感器沿用幅值/形态描述；状态通道采用状态嵌入、转移及持续时间等特征，扰动时使用合法状态集合内的替换、滞后或错配，而不是直接加连续噪声。检测器仍共享参数，增加类型输入即可保持总体结构。

STAR 支持这种数值与状态分工。对本项目，可先实现任务生成层的类型约束，再考虑修改预测损失，避免一次同时重构全部模块。若引入状态条件，只能给历史预测使用过去状态；当前已到达的状态可用于检测，不能让一步预测读取目标时刻信息。

**验证：** 先统计合成任务是否产生正常支持之外的无意义状态值，比较类型约束前后的任务泛化及正常工况切换误报。不能因为“没有变化”就删除状态通道；常量拟合段也不代表测试时该变量没有作用。

### D. 限制正常参照轨迹对异常历史的共同追随

**优先级：中高；改动量：小到中。** 当前两轨迹适配器都接收历史预测。先做一个单因素候选：正常适配器用原型自身的正常条件预测替换观测历史预测，观测适配器保持原输入。进一步可在冻结原型的 top-k 候选中加入过去状态一致性选择，避免异常片段导致参照频繁跳变。

这是从现有输入路径推导的风险，不是已证实的本次失败根因。正常状态不应被表述为真实干净反事实。过强的参照锁定也可能拒绝合法工况变化，因此不建议先直接添加强制两状态相等的损失。

**验证：** 用长于 W 的合成异常，检查预测误差衰减后是否仍保持检出；并比较短异常 ADD 与恢复误报。对应对照只替换正常适配器输入，避免同时修改门控公式。

### E. 稳定原型与多目标训练，先验证分支贡献

**优先级：中；改动量：小到中。** 在每轮现有日志中分别记录预测、边际原型、联合原型损失及有效原型数，不增加一批中间文件。先暴露可配置的原型损失权重和分支学习率，候选范围为原权重的 0.25、0.5、1 倍；必要时再独立比较码本 EMA 更新。

COMET 的正常 VQ 记忆和局部密度建模提示：原型距离还受正常模式密度影响。可将正常拟合段估计的局部尺度作为检测器的辅助证据，仍由同一检测头和一个阈值决策。测试期间保持原型冻结。不能把 COMET 的在线适应或整段统计直接移入本项目。

`Descriptor.fit` 的尺度下限为 1e-3，正常近常量特征在扰动后可能产生很大的标准化幅值。可独立比较较稳健尺度或限幅，但需检查是否损害极端真实异常的召回。本次缺少分支和原型使用率，尚不足以指定最佳码本大小。

### F. 在相同思想下优化计算细节

**优先级：效率方向中；改动量：中。** `project_relation()` 每个优化步执行 50 次二分迭代，会产生较多小算子调用；应先测其占时，再比较保持相同约束的批量单纯形投影实现。关系建模可单独比较稀疏或分组候选，但这会改变模型，需要新的效果对照。

正常历史骨干可比较单层、较小隐藏维度或更轻的因果 patch 编码，参照 PaAno 的效率方向。RTX 4080 SUPER 上可进一步评估 BF16 的历史网络计算，保留描述、状态、logit 和阈值的 FP32 精度。保持现有 PyTorch 1.11 兼容目标，不把需要升级环境的编译或新注意力 API 作为默认方案。

阶段二还可比较按任务长度分桶，减少较大 batch 的填充浪费；或在 TBPTT 块间累积梯度后更新，检查当前逐块更新对不同长度任务的隐含影响。它们不是由本次日志已经证实的错误。

**验证：** 优先测完整 epoch 秒数及峰值显存，再检查同一 seed 的验证损失与最终 22 指标。速度提升和精度保持必须分别实测。

## 7. 最小实验顺序

1. 从现有预测文件补齐 22 指标，保留当前 seed 42 基线。
2. 先执行上表的 PSM/PUMP 稳定性配置，与 `result/001` 对照；后续如需归因，分别比较阶段一学习率、阶段二学习率和早停。SMD 的阶段二 lr=3e-4、stride=4 及 SWAT 较大批量作为后续候选，每项新开实验。
3. 锁定参数选择规则后，用 seed 41–45 验证，而非把重复运行同一 seed 当作方差估计。
4. 模型细节先选择 A 或 B 的单项对照；SWAT 可优先 C。之后再比较 D、E，避免把所有候选同时叠加而失去归因。
5. 保留同冻结表征的 MLP、单 GRU、无对齐双轨迹和完整模型，验证核心状态比较机制是否超过即时证据。

正常数据上的模型选择只能验证正常覆盖和合成泛化，不能保证真实测试检测效果。当前测试结果可用于诊断并提出假设；若据此迭代，最终需要另外锁定的评价安排，不能把反复查看同一测试集后的最佳配置作为独立验证。

## 8. 操作命令与检查范围

原始预测文件仍在服务器时，快速补算标签指标，六个分数指标直接复用，不重新训练或计算 VUS：

```bash
uv run python -m asei export --root outputs/runs \
  --output "outputs/metrics_22_$(date +%Y%m%d_%H%M%S_%N).csv" \
  --recompute-labels
```

若某次运行的预测数组已移除，用模型重新评价。省略 `--config` 自动恢复原实验配置，避免旧 batch 与当前 YAML 冲突：

```bash
mkdir -p logs
nohup uv run python -u -m asei run \
  --datasets SWAT --seed 42 --gpu 0 \
  --resume 20261105_182339_241673 --stage evaluate \
  > "logs/swat_evaluate_$(date +%Y%m%d_%H%M%S_%N).log" 2>&1 < /dev/null &
```
