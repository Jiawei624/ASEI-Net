**ASEI-Net 分轮验证与代码改动规程**

当前统一方案与直接训练入口见 [OPTIMIZED_METHOD.md](OPTIMIZED_METHOD.md)。本文件保留为需要组件归因时的参考。

日期：2026-11-12。完整训练由用户在服务器执行；本地只做实现、配置解析和必要的组件检查。每批结果返回后，根据证据选择下一项改动。下面列出了完整路线，但不要求一次跑完。

**当前可以直接执行的是 V0、V1。V2—V5 是后续实现规格，相关新机制和配置项尚未加入训练代码。** 下一轮由我按本轮反馈实现，交付实际配置和命令后再运行。不要先自行添加几个 YAML 字段就启动后续实验：现有代码不会因此自动获得相应机制。

本次新增 `scripts/validation_review.py` 和 `configs/validation/round013/`，没有改动 `asei/` 下的训练或评分逻辑。配置快照源于当前本地四套 YAML；它们不是经过服务器 resolved config 核实的 012 精确复现。当前已有运行结果时可先分析旧 checkpoint，新一轮受控比较仍以同一源码和快照下的 full 为基线。

**固定实验身份与比较口径。**

| 项目 | 约定 |
|---|---|
| 数据 | 当前 TAB 数据版本及既有官方 train/test 边界；保存 source SHA-256、实体与通道清单 |
| 划分 | 保持现有正常前缀 60% fit、20% selection、20% calibration；不同独立验证记录按现有代码处理 |
| 随机性 | 先用 seed=42；有效方向再用预设的 41—45。单种子阶段只用于筛查 |
| 超参 | 每轮只改变待验证因素；模型维度、学习率、任务数、训练上限、融合预算和选模规则默认固定 |
| 工作点 | 保持 alpha=0.001、0.005、0.01；主工作点 0.01。不能按测试标签选最优 alpha |
| 指标 | 保留原始 F1、PA-F1、Affiliation-F、VUS-ROC、VUS-PR；增加持续覆盖、漏检间隙及恢复删失。五项原有指标不直接平均 |
| 状态 | 连续计算块之间传递；真实记录边界及规定的缺测条件重置；不得按测试事件边界重置 |
| 模型选择 | 使用正常及合成 selection；calibration 仅在模型锁定后使用，测试标签只用于评价 |
| 结论 | smoke 不计入论文证据；真实结果、诊断反事实和正式重训练消融分列 |

同一 alpha 并不保证不同模型有相同实际 FPR。应同时读排序指标、实际误报和事件行为。事后观察预设工作点曲线上相近 FPR 的区域可作诊断，不能据此用测试标签确定部署阈值。

**V0：核对已有 checkpoint，判断损失发生在哪里。**

本轮先不改变检测方法。若服务器还保留 012 的 `bundle.pt`、`predictions.npz` 和 `result.json`，可以直接运行诊断。否则从 V1 的新 full 开始。

当前 `runtime.save_predictions=true` 已会保存原始 U、D、分支有效性、尾秩及报警通道。首轮不加 `--diagnostics`：它会额外保存逐点逐通道的 32 维门向量，SWAT 的这一项未压缩就约为 2.94 GB，还未包括其他辅助量。也不要为补这些数据重新训练已有模型。

对一个实际存在的检测器目录执行：

```bash
python scripts/validation_review.py diagnose \
  --detector-dir /实际路径/PSM/PSM/seed_42/detectors/full
```

脚本只读 checkpoint 和逐点结果，在该目录的 `review/` 子目录输出：

| 文件 | 检查内容 |
|---|---|
| `diagnostics.json` | 实验身份、各工作点的实际误报、事件指标、分支饱和比例和未测事项 |
| `branch_scores.csv` | 原始 U、原始 D、融合分数各自的 AP、auc_pr、AUC-ROC；当前 auc_pr 的实现与 sklearn AP 相同 |
| `event_details.csv` | 事件长度、起始与后半段覆盖、超过 W/4W 部分的覆盖、最长漏检间隙、恢复延迟和删失 |
| `channel_false_alarms.csv` | 每个分支的正常误报由哪个最大分数通道触发 |

如果确实需要比较原始分支的 VUS，在同一命令末尾增加 `--with-vus`。它可能耗时较长；原主结果的 VUS 已保存在 `result.json`，常规诊断不会再次计算它。

本轮关注以下分支判断：

| 观察 | 可以支持的判断 | 下一步 |
|---|---|---|
| 原始 D 的排序明显优于秩融合，且正常与异常都有大量分数超过参考最大值 | 秩饱和或融合可能损失区分信息 | 增加评分协议对照，保持 checkpoint 固定 |
| 原始 U、D 都弱 | 单改阈值或分数映射不足以解决问题 | 检查参照、表征及任务语义 |
| 正常误报集中于少数通道 | 通道类型、参照支持或聚合可能主导误报 | 按这些通道检查正常区段与词表 |
| 事件开始有报警，W 后普遍漏检 | 值得进一步检查历史吸收和状态记忆 | 增加压缩状态回放，并做 V1、V2 |
| 点召回高而事件宏平均覆盖低 | 长事件或少数事件可能主导点指标 | 读逐事件表，不能用点召回替代持续覆盖 |

现有最小逐点文件不能直接证明“预测误差被异常历史吸收”。若这个解释仍然关键，下一次只增加压缩回放工具：在 `score_raw` 同样的分块循环中保留 `forecast` 两路误差、`norm(observed-normal)`、门最大值、`reference_index`、`peer_cost` 和支持标记，每点每通道只保存标量；不保存全部隐藏向量。正常段和测试段分别回放，不能从事件起点重置。回放应先核对与原始 U/D 一致，再检查误差随事件时间的变化。

**V1：确认双轨迹及状态监督的独立价值。首批正式任务在这里。**

本轮使用源码已有变体，无需修改 `asei/model.py`。当前快照保留原有训练预算，只修改结果目录、日志目录、seed 列表，以及保留中间文件和逐点结果。

| 对照 | 当前实现中的含义 | 状态损失 |
|---|---|---|
| `full` | 当前双轨迹与学习对齐门 | 按基线配置启用 |
| `mlp` | 状态差为零，仍读取同样的证据及冻结正常状态 | 当前代码已跳过此项 |
| `no_state` | 仍有双轨迹和门，只移除状态锚定损失 | 关闭 |
| `single_gru` | 用证据驱动的单 GRU 替代观测轨迹更新 | 本规程提供的专用配置显式设为 0 |

`mlp` 并不是完全无历史的检测器：正常状态和冻结的历史特征仍在。它用于判断额外观测状态差的增量价值。`no_state` 则不能解释为“删除双轨迹”。后续比较 `no_state`、`mlp` 与关闭状态损失的 `single_gru`，可减少给 GRU 强行施加教师坐标监督带来的混淆。

首先同步本次新增的脚本与 `configs/validation/round013/`。本仓库默认忽略根目录大部分文档，因此将本规程放在可同步的 `scripts/` 中；本轮不需要更改 `.gitignore`。

若服务器需要重新生成快照，命令是：

```bash

```

已提供快照可直接使用，不必重新生成。该命令拒绝覆盖不同内容的已有快照；若本地基础配置后来变化，使用新轮次名称。也不要把 Windows 上生成的 eligible manifest 复制到 Linux：其中包含绝对数据路径。

若数据根目录不同，使用 `--data-root /实际数据路径`，并在后续训练命令中使用同一个参数。数据清单准备是读数据检查，不能替代训练实验。新服务器或 CUDA 环境未验证时，可先运行一次既有小规模 GPU 流程检查：

这条命令内部使用小模型与合成数据，仅验证环境和流程；不要把其指标加入正式表。

**首次先反馈这 4 个结果即可。** 它们分别对应两个数据集上的 full/MLP。此时不同时改通道类型、融合权重、任务生成和选模规则。

V1 的判断按下表执行：

| 结果 | 解释与处理 |
|---|---|
| full 与 MLP 接近，或 MLP 更好 | 现有双轨迹未显示清晰增量价值；优先简化，并检查参照和任务，不继续增加状态容量 |
| full 明显好于 MLP | 再用 no_state 和 single_gru 分离状态监督、普通递归与双轨迹的贡献 |
| full 好于 no_state，但 no_state 接近 MLP | 收益更可能依赖状态监督；还不能仅归因于双轨迹结构 |
| 关闭状态监督的 GRU 与 no_state 双轨迹接近 | 可能主要受益于一般时序记忆；双轨迹需要更明确的覆盖—恢复证据 |
| 所有头的排序与覆盖都弱 | 上游信号或监督成为优先问题，进入 V3/V4 |

单种子筛查先读主 alpha=0.01 下的原始 F1、实际 FPR、事件后半段宏平均覆盖，以及全分数 VUS-PR。若一种方法 F1 更高、其余三项都不劣，记为同向优势候选；若指标互有升降，记录取舍，不按五项指标平均值选赢家。小幅差值不能证明机制有效，多种子及保留实体用于确认。

恢复延迟优先看已检出事件的版本，同时报告事件检出率、可观测恢复数和删失率。两种方法检出的事件集合不同时，再从逐事件表比较共同检出事件，避免仅因漏掉难事件而得到更短的平均恢复。测试反馈用于探索下一轮机制，不能用于挑本轮 checkpoint；经过多轮反馈的数据集属于探索集，最终确认仍需要保留实体或机制任务。

**V2：固定 MLP checkpoint，验证简单顺序证据是否已经足够。**

这是后续代码实现任务，不是当前 `--variant` 的可用选项。先实现一个固定参数的截断 CUSUM，对相同 MLP 分数做处理；不重训 MLP，也不引入多个累积器网格来挑测试最优结果。

建议的第一版定义为：

\[
p_t=p_{\mathrm{selA}}(D_t),\quad
\ell_t=\min(8,-\log p_t)-2,\quad
a_t=\min(20,\max(0,a_{t-1}+\ell_t)).
\]

数值 8、2、20 是预先固定的启动设置，不代表最优超参。`selA` 是正常 selection 前半段的固定 D 参考；后半段只用于检查健康过程下是否仍持续累积。若健康正常块中不断碰到上限，应先判定这个累积定义不合适。不能通过最终 calibration 或测试标签修正它。

| 修改位置 | 实现要求 |
|---|---|
| 新增 `asei/sequential.py` | 实现独立的标量状态更新及固定参考的尾秩查询；跨块保留状态，不回填历史 |
| `pipeline.py` 正常/测试回放 | 使用固定 MLP 原始 D 推进 a；正常记录完整顺序回放，末尾 calibration 才形成 a 的最终参考 |
| `calibration.py` 调用接口 | 仍使用现有两路校准，将动态输入由 D 替换为 a；即时 U 和预算保持不变 |
| bundle 与 `StreamingDetector` | 保存顺序参考和参数；独立测试记录从零开始，明确连续记录才继承正常结束状态 |
| 诊断与结果标记 | 同时保存 D、a 和两套校准来源；标为 MLP+固定后处理，不把它当作重新训练的检测头 |

不可评分时先按当前记录接口重置累积器；计算块边界不重置。selection 参考与最终 calibration 必须分开。带时间相关性的正常尾秩不能自动给出随时有效的顺序误报保证。

必要本地检查只有：整段/分块更新一致、缺测重置、正常负增量能退出、保存加载后连续输出一致。服务器使用 V1 的 MLP checkpoint 前向回放正常记录和测试记录，不再训练预测器或检测头。

比较 MLP、MLP+CUSUM 与 full：如果覆盖提高但正常误报或恢复拖尾同时增加，属于报警持续化的取舍；如果简单累积达到 full 的共同表现，优先采用简单方案。只有它不足以解决已观察问题时，才考虑可学习的事件状态和恢复门。

若进一步训练事件状态，需要同时修改 `TrajectoryState`、`initial_state`、`detach`、流式 bootstrap 和 bundle 保存加载。不能只在一次测试回放中添加局部变量，也不能让事件状态从测试真实事件边界获得重置。

**V3：先验证外部参照，再考虑候选分布。每项单独成轮。**

V3a 先检验相关通道选择，优先在 PUMP、SWAT 上运行。可保留 V1 表现较合适的检测头，但当前 full 与新 full 必须有同源码的对照。

| 修改位置 | 最小实现规格 |
|---|---|
| `settings.py` | 新增并校验 `memory.reference_peer_mode: all/normal_topk` 和 `memory.reference_neighbors`，默认 all；不能默默忽略非法值 |
| `normal.py::NormalMemory` | 注册冻结的 peer mask；初版从正常预测器的非对角关系绝对值选择至多 4 个外部通道，记录无有效边的情况 |
| `training.py` 正常阶段 | 在预测器与正常记忆锁定后构建 peer mask；不使用测试观测挑邻居 |
| `prepare_peers`、`reference` | 仅在可用邻居内计算外部代价，保留目标排除和既有尺度；无有效外部通道时使用既有边际/正常先验回退 |
| `model.py`、诊断 | 输出有效邻居数、外部匹配代价和参照支持情况；先不改变状态单元和动态读出结构 |
| 模型与缓存身份 | 新增缓冲区后更新包格式；参照设置必须进入正常/教师身份与路由身份；生成新的尺度、路由及任务缓存 |

4 个邻居是固定起点。若学习关系几乎全为零，应报告外部支持不足，不能通过行归一化把很弱的关联强行放大为可靠关系。先使用固定的正常关系，避免在线“可靠性权重”经其他通道分数把目标信息绕回自己的参照。

每种参照机制都需要按该机制训练正常教师的闭环目标。当前教师 checkpoint 路径在每个 seed 下共享，因此参照模式改变时使用新的 Run ID，不覆盖 V1 中的 `teacher.pt`。首次可用同一旧教师做路由敏感度回放，但它只是诊断，不替代完整新方法训练。

本地验证目标轨迹扰动后自己的参照不变、无邻居回退有效、缺测及块边界一致；再在正常 selection 检查闭环误差、正常切换误报和参照跳变。正常模型过不了这些检查时，先定位原因，不直接增加检测训练预算。

V3a 的正式对照仅为 all 与 normal_topk，保留相同原型数、检测头、任务、损失和融合权重。若差异成立，再做相同可信关系下的候选分布 V3b。

V3b 需要显式表示多解，不能把多个正常值平均后当作正常状态。第一版让状态推进继续使用原来的 MAP 原型，仅改变检测证据：

\[
R_{i,t}=-\log\sum_{k=1}^{K}\pi_{i,k,t}\,p_0(v_{i,t}\mid i,k).
\]

| 修改位置 | 最小实现规格 |
|---|---|
| `NormalMemory.reference` 附近 | 返回稳定排序的候选索引与代价，K=1 时保留原 MAP 及并列规则；权重只用外部观测和目标正常旧状态 |
| `training.py` 新增正常分布拟合 | fit 段估计局部均值/收缩协方差；低样本组向通道全局统计回退；离散状态对使用平滑概率 |
| `model.py::frozen_block` | 计算 R、候选熵与支持量，只作为检测证据；初版不改即时 U，先隔离动态分支效应 |
| 证据编码 | 当前输入维数 90、数值切片 80、能量和掩码位置是硬编码，须改为显式布局；不能只把 Linear 的输入改成 93 |
| 路由缓存 | 原缓存只保留单个索引，不含候选权重。初版从上一正常状态重新计算候选，避免把旧单索引误作完整候选；后续缓存优化另计版本 |
| 校准与结果 | 重新训练检测头并独立校准；新增原始 R 的诊断结果，确认它确实增加了区分信息 |

对照为不加入分布证据、K=1 的条件分布、K=4 的混合分布。为控制头容量，可在同一新版输入布局中为“不加入”组填零，并记录它是新版受控基线。连续分布用低维收缩协方差起步；候选温度、收缩强度首先固定，正常选择段通过后再运行真实测试。

本地需要验证目标排除覆盖候选权重的全部计算路径、概率计算数值稳定、未知符号不会被自动判正常、MAP 不受目标实际值影响、块回放一致。任何只用整体测试分数挑出的温度或候选数，都不能作为确认性结果。

V3 的成功依据是正常参照歧义区域误报减少，同时故障内部的排序和覆盖保留。仅有全部分数下降、点召回同步下降，不能解释为参照更准确。

**V4：保持架构与选模，单独改任务语义。**

优先从真实正常切换取背景，使相同局部形态在不同外部上下文中分别承担正常与异常角色。干净成员必须有可核对的正常依据；不能仅因另一个模型给出低分就认定它正常。

| 修改位置 | 实现要求 |
|---|---|
| `tasks.py` | 新增 `task_protocol` 或生成模式；记录背景、上下文、形态身份、边界平滑、实际受影响通道、拒绝原因 |
| 正常背景采样 | 优先选真实正常记录中的不同运行条件；先建立合法背景，再克隆并施加故障，使配对正常成员本身就是正确的教师目标 |
| 干预 | 将相同模板放入不同条件；匹配幅值、时长与拼接差分；关系任务分开记录边界和内部 |
| `training.py::build_pairs` | 新任务模式进入缓存身份；若改动了干净背景数值，必须重算其预测误差、路由和教师状态，不能沿用原 source 的缓存 |
| 损失与选模 | 第一轮保持 BCE、状态、尾部及配对权重不变，保持同一选模规则；不同时引入新对比损失 |

当前 `validate_pair_observability` 和 `phase_weights` 要求任务至少有一个可评分正事件。不能直接把“全正常任务”的 labels 设为零送入现有训练器。第一版让每对任务仍有正事件，增加的合法变化同时存在于 clean 与 corrupt 的正常背景中，保持教师目标一致。若以后增加独立全正常任务，需要显式修改任务类型、权重归一化和状态监督，而不是绕过校验。

可辨识性检查仍要保留，但它只证明观测改变。新生成器不能读取最终检测分数判断任务是否异常；不确定是否合法的候选不强标为故障。没有物理因果依据时，将任务称为统计依赖干预。

正式对照先固定为旧任务与新任务两组，确保原始背景来源和任务总数可比。然后做一个完整留出的扰动族：例如关系族同时从训练与合成模型选择中移除，最后仅用于机制检验。旧、新生成器在这个实验中都使用同样的留出规则，不能与训练过全部四族的版本混在同一消融结论中。

评估新任务的收益，应重点看正常困难区段误报、边界以外的异常内部覆盖和留出族表现。若收益仅在拼接起止附近出现，应继续修正生成器。

**数据类型与评分协议只在诊断支持时单独加一轮。**

SMD 的低基数、fit 常量通道应先核对真实变量定义。若证据支持它是连续变量，再通过 `data.channel_types` 显式指定类型，并完整重建正常模型、词表、教师、尺度和配对。未确认语义时，把“按连续数值处理”标为诊断假设，不覆盖主基线，也不把表示修正当作新的检测机制贡献。

若 V0 明确显示秩饱和损失，应固定 checkpoint，增加正常数据拟合的连续评分对照，并保留原工作点输出。阈值协议与模型改动分开；不可更换分数后把指标提升都归给模型。有限经验秩的尾部外推不自动保留原有校准解释。

SMD 的单序列与原始多机器实验也应分开。只有核对拼接映射后才能恢复实体边界；新协议中的状态不跨实体传播。不能仅凭总长度推测拼接顺序后改数据。

**V5：组合有效因素并冻结确认方案。**

从前几轮挑出有明确独立作用的两个因素，做 2×2 对照：均关闭、仅因素一、仅因素二、两者同时启用。不要一开始同时组合候选分布、生成器、事件状态和新阈值。若三个因素都需要保留，先完成前两个因素的归因，再验证第三个。

所有组合使用同一源码版本、数据、正常划分、任务来源和预定工作点。分别报告参数量、冻结模型成本、任务数、实际 epoch、checkpoint 选择及推理成本。候选检索增加的计算必须计入，而不能只数可训练参数。

方向稳定后，在四个数据集补种子 41—45；用未用于多轮优化的实体或机制任务确认泛化。固定实体上的多种子描述优化随机性，跨实体结论以实体为单位。不能把重叠窗口当独立重复。实际 FPR、事件覆盖和恢复删失应与五项原指标一起返回。

**每次变更时的源码与缓存规则。**

当前 `implementation_fingerprint()` 对整个 `asei/*.py` 集合取身份。修改其中任何文件都会影响正常阶段身份，直接续用旧 Run ID 会被拒绝；这是现有实现行为。当前新增的 `scripts/` 工具不改变这个指纹。

同一轮内的已有变体可共享 Run ID；修改参照、正常模型、任务机制或核心源码后使用新 Run ID。后续若要节省正常阶段重复训练，应由我实现带来源检查的显式冻结模型导入接口，并校验参数、数据和路由兼容性；不要改 key 或复制 checkpoint 来绕过检查。

修改前保留原配置和源码差异。旧结果、CSV、日志、checkpoint 不覆盖。每轮新配置放入新的固定目录。正常参照变化后，重算依赖它的教师闭环、能量尺度、路由、任务特征及校准；单改检测头则复用已经核实的正常模型。生成器变化后重建任务，不能沿用旧标签或背景特征。
